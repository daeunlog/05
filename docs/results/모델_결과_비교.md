## 버전 설명

| 버전 | 바꾼 점 |

## 알게 된 것

1. **scheme 지름길**: URL을 그대로(raw) 넣으면 원본 val 0.93이지만 `http://`만 바꿔도 0.52~0.58 → strip 계열 정규화 사용
2. **홈페이지 편향**: 학습 데이터에서 '도메인만 있는 URL' 비율이 피싱 26%, 정상 11%
3. **'/' 지름길**: 보강(v3) 후 모델이 끝 '/'를 정상의 신호로 씀 → v3의 Tranco 개선은 형식 덕. '/'를 지운 v4는 다른 출처(PhiUSIIL) 구분 능력이 크게 오름(AUROC 0.43 → 0.85)
4. **맞바꿈**: v4는 다른 출처 일반화가 좋아진 대신, 같은 출처 test에서 오탐·미탐이 늘어남. 학습 데이터 하나의 편향을 헤드 학습만으로 없애는 데 한계가 있음

## 최종 결정

- 사전 기준(test 오탐·미탐이 v3보다 나빠지지 않으면서 PhiUSIIL·Tranco 오탐이 낮을 것)에 따라 **최종 모델 = v3**
- 단, v3는 홈페이지 판단이 끝 '/' 유무에 의존함. `https://naver.com`처럼 '/' 없는 주소는 PhiUSIIL처럼 대부분 악성으로 판정될 가능성이 큼 → 서버·발표 자료에 한계로 명시
- 다른 출처 일반화를 더 중요하게 본다면 v4로 바꿀 수 있음 (v4 산출물도 Kaggle에 보관)
- 서버 연동 안내: `docs/model_api.md`, 서버용 모델: v3 → `model/artifacts/` (Kaggle `qsing-urlbert-train-v3` 출력에서 받아야 함), v2 → `model/artifacts_v2/`

### v5에서 알게 된 것
5. **다른 출처 정상 URL을 넣으면 정상 오탐은 확실히 줄어듦**: v4 대비 PhiUSIIL 25.5% → 10.1%, Tranco 39.9% → 23.2%, 처음 보는 도메인(holdout) 49.5% → 17.0%
6. **대신 악성을 더 놓침**: test 미탐률 8.2% → 14.6%, PhiUSIIL 미탐률 20.9% → 31.5%. 놓친 것은 대부분 피싱(피싱 Recall 0.79 → 0.68, 피싱 3,763건을 정상으로 판정)
7. 정상 데이터를 늘려 오탐을 줄이면 미탐이 늘어나는 맞바꿈이 v4에 이어 다시 나타남. 인코더를 고정하고 헤드만 학습하는 방식으로는 둘을 동시에 낮추지 못함
