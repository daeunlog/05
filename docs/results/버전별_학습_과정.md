# 버전별 학습 과정 — 무엇을 바꿨고, 어떤 값이 나왔고, 그래서 어떻게 됐나

> 작성: 2026-11-13 · 모든 수치는 Kaggle 실행 로그에서 옮긴 값 · 표로만 보려면 `모델_결과_비교.md`

## 0. 먼저 알아둘 것

### 모든 버전에 공통인 것
- **모델 구조**: URLBERT(`urlbert-tiny-v6`)가 URL 글자를 숫자 256개로 바꿈(임베딩) → 우리가 만든 작은 분류기(헤드)가 그 숫자를 보고 4종(정상·피싱·malware·defacement) 중 하나로 판정
- **학습하는 부분은 헤드뿐**. URLBERT 본체(인코더)는 고정이라 한 번도 바뀌지 않음
- **학습 설정**: AdamW, 학습률 0.001, 배치 2,048, 최대 30 epoch, val 점수가 3 epoch 연속 안 오르면 중단, 클래스 수 차이는 가중치로 보정
- **데이터 나누기**: Malicious URLs 632,812건을 도메인 단위로 train 442,969 / val 94,922 / test 94,921로 분리. 같은 도메인이 두 세트에 걸치지 않음(교집합 0)
- **헤드 고르는 법**: val 세트에서 Macro F1을 여러 형태(원본, `http://` 뗀 것, `https://` 붙인 것, v3부터는 홈페이지 형태)로 재서 **가장 낮은 값이 가장 높은** 헤드를 선택
- test 세트와 외부 데이터는 선택이 끝난 뒤 한 번만 평가

### 지표 읽는 법
| 지표 | 뜻 | 좋은 방향 |
|---|---|---|
| Macro F1 | 4종을 고르게 잘 맞히는 정도 (0~1) | 높을수록 |
| 정상 오탐률 | 정상 URL을 악성이라고 한 비율 | 낮을수록 |
| 악성 미탐률 | 악성 URL을 정상이라고 놓친 비율 | 낮을수록 |
| AUROC | 정상과 악성을 구분하는 능력. 0.5면 동전 던지기, 1이면 완벽 | 높을수록 |

### 평가에 쓴 데이터
| 이름 | 무엇 | 왜 보나 |
|---|---|---|
| test | Malicious URLs의 15% (94,921건) | 학습 데이터와 같은 출처에서의 성능 |
| PhiUSIIL | 다른 연구팀이 만든 정상 125,007 + 피싱 73,464 | 처음 보는 출처에서도 통하는지 |
| Tranco | 인기 사이트 첫 화면 주소 9,093건 | 유명한 정상 사이트를 악성이라 하지 않는지 |
| OpenPhish | 11/12에 받은 최신 피싱 275건 | 요즘 피싱을 잡는지 |
| JPxxx holdout (v5만) | Common Crawl 정상 20,000 + PhishTank·URLhaus 계열 악성 20,000, 학습에 없는 도메인 | 처음 보는 도메인에서의 성능 |

## 1. v2 — 처음 제대로 돌린 버전 (11/12)

**바꾼 것**: 없음. 설계대로 첫 실행. (v1은 데이터 나누기 검사에서 멈춰 결과가 없음)

**학습 데이터**: Malicious URLs train 442,969건

**학습 중 나온 값** — 입력 형태 2가지 × 헤드 2가지를 모두 학습해 val에서 비교
| 입력 형태 | 헤드 | val Macro F1 (원본) | val Macro F1 (주소 앞부분을 바꿨을 때 최저) |
|---|---|---|---|
| raw (URL 그대로) | linear | 0.8975 | 0.5169 |
| raw | mlp | 0.9339 | 0.5772 |
| strip (`http(s)://`, `www.` 제거) | linear | 0.7732 | 0.7732 |
| strip | mlp | **0.8287** | **0.8287** ← 선택 |

- raw는 점수가 0.93으로 제일 높아 보이지만 `http://`를 떼거나 `https://`로 바꾸기만 해도 0.52~0.58로 무너짐
- 이유: 학습 데이터에서 defacement는 100%가 `http://`로 시작하고 정상은 92%가 앞부분이 없음. 모델이 내용이 아니라 **주소 앞부분 모양으로 맞히는 지름길**을 배운 것
- 그래서 앞부분을 지우는 strip + mlp를 선택. 시드 3개 평균 0.8289 ± 0.0003 (거의 흔들리지 않음)

**결과**
| 어디서 | 값 |
|---|---|
| test | Macro F1 0.826, 정상 오탐률 19.7%, 악성 미탐률 2.8% |
| PhiUSIIL | AUROC 0.43, 정상 오탐률 **99.2%**, 악성 미탐률 4.3% |
| Tranco | 정상 오탐률 24.1% |
| OpenPhish | 악성 미탐률 7.3% |

**그래서**: 같은 출처(test)에서는 쓸 만해 보이지만, 다른 출처의 정상 URL은 거의 전부 악성이라고 함. AUROC 0.43은 동전 던지기(0.5)보다 나쁨. 서비스에 그대로 쓰기 어려움 → 원인을 찾기로 함

## 2. v3 — 정상 홈페이지 주소를 만들어 넣음 (11/12)

**원인 조사**: 클래스별로 "도메인만 있는 주소(홈페이지 형태)" 비율을 재 봄
| 데이터 | 정상 | 피싱 | malware | defacement |
|---|---|---|---|---|
| Malicious URLs | 11.18% | 25.87% | 4.28% | 0.00% |
| PhiUSIIL | 100.00% | 69.19% | — | — |

- 학습 데이터에서는 홈페이지 형태가 피싱 쪽에 2.3배 많음 → 모델이 "도메인만 있으면 피싱"이라고 배움
- 그런데 PhiUSIIL 정상 URL은 100%가 홈페이지 형태 → 전부 악성 판정

**바꾼 것**: 학습 데이터의 정상 URL에서 호스트를 뽑아 `https://호스트/` 주소를 만들어 정상으로 추가. 악성에 한 번이라도 나온 호스트는 제외. 추가량: train 35,659 / val 24,439 / test 24,458

**학습 중 나온 값**: strip + mlp, val Macro F1 원본 0.8217, 홈페이지 val 0.8260, 최저 0.8217. 시드 평균 0.8278 ± 0.0053

**결과 (v2 → v3)**
| 어디서 | v2 | v3 |
|---|---|---|
| test Macro F1 | 0.826 | 0.821 |
| test 정상 오탐률 / 악성 미탐률 | 19.7% / 2.8% | 19.6% / 3.1% |
| 만든 홈페이지 주소(test) 정상 오탐률 | — | 2.7% |
| Tranco 정상 오탐률 | 24.1% | **7.0%** |
| PhiUSIIL AUROC / 정상 오탐률 | 0.43 / 99.2% | 0.43 / **98.6%** (그대로) |
| OpenPhish 악성 미탐률 | 7.3% | 11.3% |

**그래서**: Tranco는 크게 좋아졌는데 PhiUSIIL은 전혀 안 변함. 둘 다 홈페이지 주소인데 왜 다를까 → 형식을 비교해 보니 Tranco와 만든 주소는 `naver.com/`처럼 **끝에 '/'가 있고**, PhiUSIIL은 `naver.com`처럼 **없음**. 모델이 "끝에 '/'가 있으면 정상"이라는 새 지름길을 배웠을 가능성 → v4에서 확인

## 3. v4 — 홈페이지 끝 '/'를 지워 형식을 통일 (11/12)

**바꾼 것**: 입력 정리 방식에 한 단계 추가(strip2). `naver.com/`과 `naver.com`을 같은 입력으로 만듦. 학습 데이터는 v3와 같음

**학습 중 나온 값**
| 헤드 | val Macro F1 (원본) | 최저 |
|---|---|---|
| linear | 0.7510 | 0.7300 |
| mlp | 0.7870 | **0.7723** ← 선택 |

- 시드 평균 0.7874 ± 0.0102. v3(0.82)보다 val 점수가 낮아짐 = '/'라는 쉬운 단서가 사라져 문제가 어려워짐

**결과 (v3 → v4)**
| 어디서 | v3 | v4 |
|---|---|---|
| test Macro F1 | 0.821 | 0.785 |
| test 정상 오탐률 / 악성 미탐률 | 19.6% / 3.1% | 24.2% / 8.2% |
| PhiUSIIL AUROC | 0.43 | **0.85** |
| PhiUSIIL 정상 오탐률 / 악성 미탐률 | 98.6% / 7.1% | **25.5%** / 20.9% |
| Tranco 정상 오탐률 | 7.0% | 39.9% |
| OpenPhish 악성 미탐률 | 11.3% | **4.7%** |

**그래서**
- '/' 지름길 가설이 맞았음. '/'를 지우자 Tranco가 7% → 40%로 되돌아감(v3의 개선은 형식 덕이었음)
- 반대로 다른 출처에서 정상·악성을 구분하는 능력은 처음으로 생김(AUROC 0.43 → 0.85)
- 대신 같은 출처 test는 나빠짐. 미리 정한 기준("test 오탐·미탐이 v3보다 나빠지지 않을 것")에 걸려 **최종은 v3, 대안은 v4**로 결정

## 4. v5 — 다른 출처의 정상 URL 20만 건 추가 (11/13)

**왜 다시 했나**: "학습 데이터가 하나뿐이냐"는 질문으로 다시 조사해 보니, Malicious URLs의 정상 URL은 ISCX-URL-2016에서 왔고 그 데이터는 만들 때 **도메인만 있는 URL을 일부러 뺐음**. 즉 v2~v4의 문제는 데이터를 만든 방식에서 온 것이라, 같은 데이터 안에서 형식만 손봐서는 한계가 있음

**바꾼 것**: v4 설정 그대로 + HuggingFace `JPxxx/url-benchmark-dataset`의 정상 URL(Common Crawl에서 모은 것) 200,000건을 **train에만** 추가. val·test·외부 평가는 v4와 완전히 같게 둬서 바로 비교 가능

**추가 데이터를 거른 과정** (평가가 새지 않도록)
| 단계 | 남은 건수 |
|---|---|
| 정상 표본 100만 건 정제 후 | 999,964 |
| val·test에 있는 도메인 제외 | 919,491 |
| PhiUSIIL·OpenPhish·Tranco에 있는 도메인 제외 | 887,321 |
| 악성 URL에 나온 호스트 제외 | 830,014 |
| 이미 있는 URL 제외 | 745,338 |
| 도메인당 최대 3건 | 514,348 |
| 그중 train에 넣은 것 | **200,000** (도메인 182,450개, 홈페이지 형태 43.6%) |
| 따로 떼어 둔 holdout (학습에 없는 도메인) | 정상 20,000 + 악성 20,000 |

**학습 데이터 합계**: 442,969 + 35,659 + 200,000 = 678,628건

**학습 중 나온 값** (mlp, 시드 42)
| epoch | 1 | 3 | 5 | 8 | 10 | 12 (최고) | 15 (중단) |
|---|---|---|---|---|---|---|---|
| 학습 loss | 0.444 | 0.289 | 0.260 | 0.232 | 0.219 | 0.209 | 0.197 |
| val Macro F1 | 0.728 | 0.763 | 0.774 | 0.783 | 0.787 | **0.791** | 0.779 |

- loss는 계속 내려가는데 val 점수는 12 epoch 이후 더 안 오름 → 15 epoch에서 자동 중단, 12 epoch 때의 헤드를 사용
- linear는 원본 0.7421 / 최저 0.7376, mlp는 원본 0.7914 / 최저 **0.7852** → mlp 선택
- 시드 3개 평균 0.7940 ± 0.0027 (v4의 ±0.0102보다 안정적)

**결과 (v4 → v5)**
| 어디서 | v4 | v5 | 방향 |
|---|---|---|---|
| test Macro F1 | 0.785 | 0.789 | 비슷 |
| test 정상 오탐률 | 24.2% | 19.5% | 좋아짐 |
| test 악성 미탐률 | 8.2% | **14.6%** | 나빠짐 |
| PhiUSIIL AUROC | 0.85 | 0.87 | 비슷 |
| PhiUSIIL 정상 오탐률 | 25.5% | **10.1%** | 좋아짐 |
| PhiUSIIL 악성 미탐률 | 20.9% | 31.5% | 나빠짐 |
| Tranco 정상 오탐률 | 39.9% | **23.2%** | 좋아짐 |
| 만든 홈페이지 주소(test) 정상 오탐률 | 20.5% | 11.4% | 좋아짐 |
| OpenPhish 악성 미탐률 | 4.7% | 5.8% | 비슷 (275건, 신뢰구간 겹침) |

**처음 보는 도메인(holdout 40,000건)에서** — 같은 실행 안에서 "보강만 뺀 헤드"도 학습해 비교
| 헤드 | AUROC | 정상 오탐률 | 악성 미탐률 |
|---|---|---|---|
| 보강 없음 (v4 재현) | 0.807 | 49.5% | 6.2% |
| v5 | **0.940** | **17.0%** | 8.5% |

- 재현한 v4 헤드의 test 수치가 11/12 v4 실행과 똑같이 나옴(Macro F1 0.7845) → 이 비교는 공정함
- 단, holdout의 정상 URL은 추가한 학습 데이터와 같은 출처(Common Crawl)이고 이 데이터는 인코더 벤치마크 계열이라, 수치가 실제보다 좋게 나올 수 있음

**그래서**
- 정상 사이트를 악성이라 하는 문제는 확실히 줄었음 (PhiUSIIL 25.5% → 10.1%, Tranco 39.9% → 23.2%)
- 그 대가로 악성을 더 놓침. 놓친 것은 거의 피싱: test에서 피싱 13,489건 중 3,763건을 정상이라고 함(v4는 2,218건). 피싱 Recall 0.79 → 0.68
- 실행 전에 정해 둔 기준 5개 중 "test 악성 미탐률 10% 이하"를 넘김(14.6%) → **v5는 최종 모델로 채택하지 않음**

## 5. 전체 흐름 한눈에

| 버전 | 고친 문제 | 결과 | 새로 드러난 문제 |
|---|---|---|---|
| v2 | (첫 실행) 주소 앞부분 지름길 → strip으로 차단 | test 0.826 | 다른 출처 정상 URL 99% 오탐 |
| v3 | 정상 홈페이지 주소 부족 → 만들어 추가 | Tranco 24% → 7% | PhiUSIIL 그대로. 끝 '/' 지름길 의심 |
| v4 | 끝 '/' 지름길 → 형식 통일 | PhiUSIIL AUROC 0.43 → 0.85 | test 성능 하락, Tranco 40% |
| v5 | 정상 데이터 출처가 하나 → 다른 출처 20만 건 추가 | 정상 오탐 큰 폭 감소 | 피싱 미탐 증가(8% → 15%) |

### 네 번의 실험에서 일관되게 확인된 것
1. 모델은 URL의 뜻보다 **데이터가 만들어진 방식의 흔적**(주소 앞부분, 끝 '/', 홈페이지 형태)을 먼저 배움. 하나를 막으면 다음 것이 드러남
2. 같은 출처 test 점수만 보면 v2가 제일 좋지만, 그 점수는 다른 출처에서 통하지 않음. **test 점수가 높다고 좋은 모델이 아님**
3. v4·v5에서 오탐을 줄이면 미탐이 늘어남. 인코더를 고정하고 헤드만 학습하는 구조에서는 둘을 함께 낮추지 못했음

### 최종 결정 (사전 기준 적용)
- **최종 모델: v3** (11/12 결정 유지), 대안: v4
- v5는 채택 기준 미달이지만 "정상 사이트 오탐을 가장 줄여야 할 때"의 후보로 보관
- 어느 버전이든 AI 점수만으로 차단하지 말고 VirusTotal 등 외부 검사와 함께 쓰는 원래 설계가 필요함

| 무엇이 가장 중요한가 | 맞는 버전 | 감수할 점 |
|---|---|---|
| 악성을 놓치지 않기 (같은 출처 기준) | v3 | 끝 '/' 없는 홈페이지 주소는 대부분 악성 판정, 다른 출처 정상 오탐 98.6% |
| 다른 출처에서도 구분되기 + 미탐 낮게 | v4 | 정상 오탐 25~40% |
| 정상 사이트 오탐 줄이기 | v5 | 피싱 미탐 15%(같은 출처), 31%(PhiUSIIL) |

### 남은 개선 방향 (이번 범위 밖)
- 인코더까지 함께 학습(파인튜닝)
- 피싱 데이터도 다른 출처로 보강 (v5는 정상만 늘려 균형이 정상 쪽으로 기움)
- 4종 대신 정상/악성 2종으로 단순화해 다른 공개 데이터를 더 쓰기
